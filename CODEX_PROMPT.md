# Prompt for Codex

You are my senior full-stack engineer and product/design collaborator. Build **TechWatch**, a mobile-first technical intelligence briefing app. This handoff folder is the source of context; read `README.md`, every file in `docs/`, and visually inspect the images in `design_references/`, especially the latest engineering onboarding and technical briefings. Inspect the existing repository and its instructions before writing code. If this folder is the whole project, treat it as a new build. Do not overwrite existing work.

The audience is developers, software/platform/cloud engineers, DevOps, SREs, product managers, engineering leaders and CTOs. They need useful, clear updates on releases, package libraries, cloud, AI models and APIs, security advisories, breaking changes and deprecations. A title alone should communicate the change; a short, accessible summary should explain what changed, why it matters, who may be affected, and what to check when supported by evidence. Preserve exact versions, CVEs, constraints and uncertainty. Never invent facts or claim a user is affected merely because they follow a product.

Design is approved: light Warm Editorial Terracotta, near-white warm background, white subtly raised cards, dark readable text, tasteful terracotta accents and shaded buttons, serif headlines and sans-serif body/controls. The images are raster reference boards, not editable Figma files; implement their spirit and correct visual inconsistencies. Screen copy/news is illustrative. Create an editable design deliverable only if a supported tool is actually available; otherwise explain limitations and deliver a runnable faithful UI without claiming Figma exists.

The app opens to Feed in Cards mode after optional onboarding. Top tabs are exactly Feed · Your Stack · Trending · AI. Vertically page between update cards, support accessible controls, and offer an explicit Cards/List switch preserving section, filter, order and current item; remember each tab's position during the session. Explore and Saved are separate navigation destinations. No forced login or push. Onboarding covers role, focus areas, technologies and alert preferences; all skippable. Users can edit preferences later. Use light backgrounds and clear responsive layout.

Engineering direction: curated trusted source registry; official APIs/RSS/releases and vendor security advisories; safe permitted crawling only when appropriate; scheduler, collectors, raw source provenance, normalization, dedupe, structured extraction, evidence validation, AI-assisted plain-language summaries, security/uncertain review gating, publication, correction, feeds and opt-in alerts. Summarize once per canonical update, personalize ranking per user. Do not imply full-web coverage. Avoid executing untrusted source instructions, prevent SSRF, protect credentials and respect source rights. PostgreSQL + FastAPI + background workers, Docker Compose and Flutter are recommended defaults; assess existing repo and document any justified changes. No production API keys, source credentials or operational budgets are included.

Work autonomously. First inspect and summarize the implementation plan, then implement a **runnable, tested end-to-end vertical slice**: optional onboarding → mock or seeded Feed/Cards → tab switching and same-item List view → search/explore → follow stack → saved item → original source action. Provide a basic source registry, ingestion contracts and an offline deterministic fixture connector. Use clearly labeled fictional sample data and keep real external integrations disabled until configured. Implement an initial admin/review path appropriate to the stage; mark what remains stubbed. Provide Compose startup, migrations, env template, build/run documentation, meaningful tests for feed continuity, security/relevance, duplicate handling and content validation, and a concise next-step list. Do not use or request a personal ChatGPT login or user-side provider key. Never commit secrets or silently deploy/send messages.

Make reasonable non-destructive assumptions; call out unknown hosting, scale, budget, account/sync and notification providers. Preserve the newest decisions from this handoff over contradictory old screenshot copy. After implementing, run appropriate checks, report real results and remaining gaps, and show how to preview the app. If implementation cannot be completed, deliver all completed work and precisely identify the blocker.
